# Contracts shared between modules

Reference document for all work sessions. If a module needs to change a contract, it notes it at the end under "Proposed changes" instead of changing it silently.

Full plan: `docs/plan.md`.

## Environment
- Python 3.14.5 in `.venv` (already created). Always run with `.\.venv\Scripts\python.exe`.
- Installed packages: fastapi, uvicorn[standard], httpx, python-dotenv, mss, pillow, rapidfuzz, openpyxl, pytest, numpy, opencv-python-headless (cv2 5.0), winrt-runtime + winrt-Windows.Media.Ocr / Graphics.Imaging / Storage.Streams / Foundation / Foundation.Collections / Globalization.
- Windows OCR available with the `en-US` and `es-ES` languages (already installed).
- No Node or Git. Unversioned project: each session touches **only its own files**.
- If you add a package, also add it to `requirements.txt` (only add lines).
- All user-facing text in **Spanish**. Code and identifiers in Spanish or English, but consistent within each module.

## 1. Catalog — `data/catalogo.json` (generated by `tools/importar_metabot.py`)
```json
{
  "fuente": "metabot.gg",
  "version_cliente": "0.0.4387.0",
  "generado": "2026-11-02T12:00:00Z",
  "profesiones": {"herreria": "Herrería", "armadura": "Armadura", "orfebreria": "Orfebrería", "alquimia": "Alquimia", "cocina": "Cocina"},
  "objetos": {
    "610620013": {
      "nombre": "Mineral de orichalcum",      // official ES name from the client
      "nombre_en": "Orichalcum Ore",
      "grado": "common",                      // as it comes from the source
      "icono": "https://...",                 // optional
      "comerciable": true,                    // null if unknown
      "vinculado": false,                     // "(vinculado)"/"(Bound)" in the name → true
      "precio_npc": null,                     // NPC shop price in Kinah if known
      "slug": "orichalcum-ore"                // optional
    }
  },
  "curvas": { "c9": [95.2, 95.4, 95.6] },     // success %; index = nivel_personaje − nivel_receta (clamp to the last value)
  "recetas": [
    {
      "id": 115016001,
      "faccion": "elyos",                     // "elyos" | "asmodian" | "ambas"
      "profesion": "herreria",                // key from "profesiones"
      "nivel": 1,                             // required mastery (1–100)
      "producto": 610710001,
      "cantidad": 1,
      "ingredientes": [[610620013, 2], [630541001, 1]],
      "curva": "c9",                          // null = no curve (100% / tools / transfers)
      "combo_pct": 0,                         // 0–100
      "curva_combo": null,
      "producto_combo": null,                 // product id if there is a combo (splendent version), if known
      "cantidad_combo": null
    }
  ]
}
```
Item ids are strings in `objetos` (JSON keys) and integers in `recetas`. `app/catalogo.py` exposes:
- `cargar_catalogo(ruta=None) -> Catalogo`
- `Catalogo.objeto(id) -> dict`, `Catalogo.nombre(id) -> str`, `Catalogo.recetas_de(faccion) -> list`, `Catalogo.recetas_que_producen(id) -> list`, `Catalogo.buscar(texto, limite=10) -> list[(id, nombre, puntuacion)]` (rapidfuzz, ignoring accents/case).

## 2. Data — `app/db.py`
Two backends with the same interface: **Supabase** (PostgREST via httpx, if `.env` has `SUPABASE_URL` and `SUPABASE_KEY`) and **local SQLite** (`data/aion2.db`, otherwise). With Supabase, if the network fails, writes go to `data/pendientes.jsonl` and are retried.

```python
repo = obtener_repositorio()          # picks the backend based on .env
repo.backend -> "supabase" | "local"

# servers / profiles
repo.listar_servidores() -> list[dict]           # {id, nombre, faccion, region, comision_registro, impuesto_venta}
repo.guardar_servidor(dict) -> dict
repo.listar_perfiles() -> list[dict]             # {id, nombre, servidor_id}
repo.guardar_perfil(dict) -> dict
repo.niveles(perfil_id) -> dict[str, int]        # {"herreria": 12, ...}
repo.guardar_nivel(perfil_id, profesion, nivel)
repo.inventario(perfil_id) -> dict[int, int]     # objeto_id -> total quantity (inventory + warehouse)
repo.inventario_detalle(perfil_id) -> list[dict] # {objeto_id, cantidad, ubicacion}
repo.guardar_inventario(perfil_id, objeto_id, cantidad, ubicacion="inventario")

# market
repo.guardar_lecturas(lecturas: list[Lectura], sesion_id: str|None) -> ResultadoGuardado
repo.verificar_lecturas(ids: list[str]) -> bool   # re-reads and confirms they exist and are complete
repo.ultimas_lecturas(servidor_id) -> dict[int, Lectura]           # the most recent one per item
repo.historico(servidor_id, objeto_id, desde: datetime) -> list[Lectura]
repo.subir_pendientes() -> int                    # drains the offline queue; returns the number uploaded

# other
repo.precios_npc() -> dict[int, float]; repo.guardar_precio_npc(objeto_id, precio)
repo.ajustes() -> dict; repo.guardar_ajustes(dict)
repo.registrar_operacion(perfil_id, tipo: "venta"|"compra", objeto_id, cantidad, precio, fecha)
```
```python
@dataclass
class Lectura:
    servidor_id: str
    objeto_id: int
    fecha: datetime                 # UTC
    precio_min: float | None
    cantidad_total: int | None      # units on offer
    num_anuncios: int | None
    ofertas: list[tuple[float, int]]  # order book [(precio, cantidad)] sorted by price
    fuente: str                     # "grabacion" | "video" | "captura" | "manual" | "excel"
    id: str | None = None           # uuid assigned on save
```
`ResultadoGuardado`: `{ids: list[str], en_cola: bool}` (en_cola=True if it ended up in the offline queue).

Default settings: `{"comision_registro": 0.02, "impuesto_venta": 0.10, "rebaja_listado": 1, "combo_fallido": "pierde_todo", "valorar_inventario": "mercado", "tope_tmp_mb": 500}`.

## Proposed changes
- **[data, 2026-11-02] Compatible extensions of `app/db.py`** (everything in the contract works the same):
  - `ResultadoGuardado` also has `error: str | None` (reason if it was queued).
  - `historico(servidor_id, objeto_id, desde=None, con_ofertas=True)`: `desde=None` = everything; `con_ofertas=False` avoids downloading the order book (faster for `volumen_estimado`).
  - `guardar_lecturas` assigns `lectura.id` (uuid) on the object itself and sorts `lectura.ofertas` by price. It validates `fuente`; if invalid it raises `ValueError` (does not queue).
  - `verificar_lecturas([])` returns True. It returns False (does not raise) if any reading is queued, doesn't exist, is missing offers or there is no connection.
  - `registrar_operacion(..., fecha=None)` → `dict` with the `id`; `precio` is **per unit**. Without network, on Supabase it goes to the queue (`"en_cola": True`).
  - Extras: `repo.operaciones(perfil_id=None, desde=None) -> list[dict]`, `repo.num_pendientes() -> int`, `repo.pendientes() -> list[dict]` (Supabase only: queue summary with errors), `repo.sincronizar_catalogo(datos_catalogo_json) -> dict` (copies the catalog to the `objetos`/`recetas`/… tables), `repo.cerrar()`.
  - `guardar_inventario(..., cantidad<=0)` deletes the row; `guardar_precio_npc(id, None)` deletes the price.
  - `guardar_servidor` / `guardar_perfil` without `id` generate a uuid; with `id` they update only the given fields. `faccion` is normalized to lowercase and must be `elyos` | `asmodian`. The server's `comision_registro`/`impuesto_venta` can be null (= use the global setting).
  - Errors: `app.db.ErrorBaseDatos` (and its subclass `ErrorRed` for lack of connection).
  - Security (for the API): the dashboard never talks to Supabase directly; the secret key only lives in the backend. It is recommended that uvicorn listens on `127.0.0.1`, not on `0.0.0.0`.
- **[engine, 2026-11-02] Compatible extensions of `app/calculo.py` / `app/precio_objetivo.py`** (the contract signatures work the same):
  - **For the catalog**: the engine accepts the raw `catalogo.json` `dict` or a `Catalogo` object. From the object it needs to read the curves and the full recipe list: please have `Catalogo` expose `.datos` (the raw dict) **or** `.curvas` (dict) + `.recetas` (list) + `.objetos` (dict). Without that, it can only use `recetas_de("elyos"/"asmodian")` and will assume 100% for the curves.
  - `precios[id]` (InfoPrecio) can be a dict or a `Lectura`; optional extra fields: `precio_npc`, `volumen_dia` (from `volumen_estimado`, to warn about saturation). NPC prices can also be passed as the kwarg `precios_npc={id: precio}` or taken from the catalog's `objetos[id].precio_npc`.
  - `analizar_receta(..., *, niveles=None, faccion=None, precios_npc=None, ahora=None)`: `niveles` is needed to value ingredients crafted with **another** profession; `ahora` (UTC) for tests.
  - `coste_adquisicion(objeto_id, cat, precios, ajustes=None, niveles=None, faccion=None, inventario=None, precios_npc=None)`.
  - `mejores_oportunidades(..., *, precios_npc=None, ahora=None)`; `filtros`: `profesion` (str|list), `inversion_max`, `margen_min` (fraction), `incluir_intermedios` (True), `solo_desbloqueadas` (True), `solo_rentables` (True), `incluir_sin_precio` (False), `tope_intentos`, `ordenar_por` ("beneficio_total"|"beneficio_intento"|"margen"), `limite`. Each result adds `intentos_recomendados`, `inversion` (Kinah to spend), `es_intermedio`.
  - Extra keys in `analizar_receta`: `receta_id, producto, nombre, profesion, nivel_receta, nivel, intentos, p_exito_simple, p_combo_activado, p_combo_fallido, salidas_esperadas {id: unidades}, coste_total, coste_por_objeto, precio_venta, beneficio_total, intentos_con_inventario, faltan [{id, nombre, faltan, coste}], coste_faltante, mensaje_inventario`. In `desglose_ingredientes` also: `unidades_necesarias, en_inventario, faltan, origenes {origen: unidades}, coste_total, coste_faltante, receta_id`. `p_combo` = P(**successful** combo). Probabilities as a 0–1 fraction. `max_intentos_mercado=None` = no known limit (no order book or quantity).
  - New settings (with defaults): `horas_precio_antiguo` 24, `max_anuncios` 10, `unidades_por_anuncio` 1, `anuncios_saturado` 50, `dias_saturado` 7, `tope_intentos` 100, `nivel_por_defecto` 1, `rebaja_saturado_pct` 0.03, `min_lecturas_historico` 3, `horas_min_volumen` 12.
  - `precio_objetivo_venta(historico, actual=None, ajustes=None, *, unidades=1, ventana_dias=None, ahora=None)`; also returns `precio_actual, cantidad_en_oferta, n_lecturas`. `precio_objetivo_compra(historico, actual=None, ajustes=None)`; `estado`: "oportunidad"|"normal"|"caro"|"sin_datos"; also returns `mediana, precio_actual, aviso`.
- **[catalog, 2026-11-02] Compatible extensions of `data/catalogo.json` and `app/catalogo.py`** (everything in the contract is there and works the same):
  - **`nivel` can be 0** (190 recipes, `"tipo": "mejora"`): metabot labels them "Mejora"/"Upgrade"; they have no curve (`curva: null`). The real range is 0–100.
  - Faction: 2nd digit of the recipe id, `1 = elyos`, `2 = asmodian` (verified: 129 rows of metabot's tables and 81 recipes with faction ingredients, 0 contradictions). `"ambas"` is not used: mirror recipes are stored separately because their products have **different ids per faction** (116 item names are repeated with one id per faction). The OCR must disambiguate names with the server's faction → `buscar(texto, faccion=...)`.
  - Extra fields in `objetos[id]`: `faccion` ("elyos"|"asmodian"|"ambas"|null, according to the recipes that use/produce it), `precio_venta_npc` (what the merchant pays), `comercio` (metabot text: "Comerciable" (tradeable), "No comerciable" (not tradeable), "Ligado al alma" (soul-bound)…), `tienda_npc`, `recoleccion` (gathering node, if applicable).
  - `comerciable`: true = "Comerciable" (132), false = "No comerciable" (58). **All crafted equipment (456 items) is "Ligado al alma"** (EN "Soul-bound"): it's unclear whether it can be sold before binding, so it is `null`. To be confirmed in game; the engine should not discard those recipes just because of `null`.
  - Extra fields in `recetas[]`: `tipo` ("normal"|"mejora"). Root: `atribucion`, `notas` (list[str]), `evidencia_faccion`, `max_maestria`.
  - `producto_combo`/`cantidad_combo`: **inferred** (metabot doesn't publish them) for equipment only: the "brillante"/"Splendent" version of the product (228 recipes; those items have no normal recipe). Food, potions and stones (52 recipes with combo) → null. The 114 dragon-king brilliant versions also have their own "mejora" recipe.
  - `app/catalogo.py` extras: `Catalogo.datos/objetos/recetas/curvas/profesiones`, `receta(id)`, `recetas_que_usan(id)`, `buscar(texto, limite=10, faccion=None)` (`int` ids, score 0–100), `prob_exito(receta, nivel) -> float|None` (None = locked; null curve = 1.0), `prob_combo(receta, nivel)` = success × combo_pct × combo success (matches metabot: 13.51% in the example on their site). `objeto(id)` returns `None` if it doesn't exist; `nombre(id)` returns `"#id"`. `recetas_de(None)` = all; accepts aliases "Asmodianos", "elios"…
- **[capture, 2026-11-02] Compatible extensions of `app/captura/`** (the contract signatures work the same; everything new is optional kwargs or extra keys):
  - `FilaMercado` also carries: `nombre` (official catalog name), `total` (total listing price if it was read), `motivos: list[str]` (why it is doubtful, in Spanish), `caja: [x, y, w, h]` (area of the row in the image) and, in recording/video, `recorte` (path of the doubtful row's PNG in `capturas/tmp/revision/`). `precio`/`cantidad` are `int`.
  - **Faction**: since some names are repeated with one id per faction, all entry points accept `faccion="elyos"|"asmodian"` (the server's) and pass it to `cat.buscar(..., faccion=)`. Without a faction, those rows come out doubtful with the reason "existe en las dos facciones" (exists in both factions). The integration must pass the selected server's faction.
  - `ocr.leer_imagen(img, region=None, idioma="es-ES", escala=None, invertir=None, umbral=None)`; extras `ocr.reconocer(img)`, `ocr.preprocesar(img)`, `ocr.idiomas_disponibles()`. It is safe to call from threads and from async code (dedicated winrt loop; calls are serialized because an `OcrEngine` doesn't support two at once).
  - `parser.interpretar_pantalla(lineas, cat, columnas=None, orden_numeros=("precio","cantidad"), faccion=None)`. `cat` can be a `Catalogo`, the `catalogo.json` dict, `{id: nombre}` or an already built `parser.IndiceNombres(cat, faccion)` (faster for many screens). Extras: `parser.agrupar_libro(filas, incluir_dudosas=False) -> {objeto_id: {ofertas, precio_min, cantidad_total, num_anuncios, nombre}}`, `parser.consolidar(lista_de_filas_por_fotograma)`, `parser.a_lecturas(filas, servidor_id, fuente, fecha=None, incluir_dudosas=False) -> list[Lectura]` (uses `app.db.Lectura`; excludes doubtful rows by default).
  - `grabacion.SesionGrabacion(fps=3, cat=None, region=None, columnas=None, fuente=None, monitor=None, guardar_recortes=True, al_leer=None, idioma="es-ES", faccion=None)`: `.iniciar()`, `.detener() -> list[FilaMercado]` (raises `RuntimeError` if the thread failed), `.estado() -> dict` (for polling from the UI), `.activa`. Extra `grabacion.procesar_imagen(img, cat, region=None, columnas=None, escala=None, faccion=None)` (a single screenshot; also used by the watcher).
  - `video.procesar_video(ruta, cat, region=None, columnas=None, fps_muestreo=3, guardar_recortes=True, progreso=None, faccion=None, devolver_estadisticas=False)`.
  - `vigilante.Vigilante(carpeta=None, cat=None, intervalo=2, al_procesar=None, al_error=None, faccion=None)`: `.iniciar()/.detener()/.revisar()/.recoger()/.estado()`.
